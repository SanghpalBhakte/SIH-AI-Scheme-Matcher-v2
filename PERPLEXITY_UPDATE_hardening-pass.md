# Handoff to Perplexity: SIH judging hardening pass (Sept 3, 2026)

## Quick recap

SchemeSetu (SIH26092) — Next.js/TypeScript app matching Indian entrepreneurs to real government schemes via a deterministic rule engine (no ML/LLM in the matching path). This was a 5-task hardening pass ahead of judging: real document/step data for the most demo-visible schemes, a global error boundary, an honest "data confidence" indicator, a machine-translation notice, and persisted application-checklist progress. No matching logic, weights, thresholds, or existing eligibility fields were touched. Dataset stays at 34 real schemes.

## What changed, task by task

1. **Real requiredDocuments/applicationSteps, source-checked, not guessed.** Re-fetched the cited official source for each of the 3 demo-profile top matches (`stand-up-india`, `mudra-tarun`, `nstfdc-term-loan`) plus the 4 state schemes with an existing `officialUrl`/`sourceUrl` (Delhi, Gujarat, Maharashtra, Andhra Pradesh). Only **`delhi-composite-loan-scheme`** got new data — 4 explicit application steps, sourced verbatim from its already-cited `publicservicesmap.in` page. Every other target scheme's source either had no explicit document/step list to cite or was unreachable — left honestly unset with an inline comment explaining why (see "Not completed safely" below). `stand-up-india` already had complete `applicationSteps`; needed no change.
2. **Global error boundary** at `app/error.tsx`, following the Next.js App Router convention: branded fallback reusing the existing `Card`/`Button` components, "Start over" (calls `reset()`) and "Go home" actions, `console.error(error)` logging (never swallowed). New i18n keys (`error.title`, `error.body`, `error.startOver`, `error.goHome`) added to all 12 locales. Verified against a deliberately-thrown error in a temporary scratch route (built, started the server, drove it with a headless browser to confirm the fallback actually renders and both buttons work) — then deleted the scratch route.
3. **"Data confidence" indicator.** Added `Scheme.dataConfidenceNote?: string` (optional, never read by the matching engine — grep-confirmed zero references in `lib/matching/` outside the type declaration itself). Populated it only for the 4 scheme records that already carried a genuine sourcing caveat in their own code comments: `delhi-composite-loan-scheme` (ST tier not separately stated), `karnataka-udyogini` (primary portal blocked, corroborated via secondary sources, OBC eligibility unconfirmed), `gujarat-scheme-for-assistance-startups` (primary domain unreachable, corroborated via GUSEC), `bihar-mmuy` (loan/subsidy split corroborated via secondary sources, not the primary portal). Surfaced as a small "Sourcing note:" line (new component `components/schemes/data-confidence-note.tsx`) on the scheme detail page, the browse card, and the recommendation card.
4. **Machine-translation notice** for the 10 AI-generated locales (every locale except English and Hindi, which were written/reviewed by hand — this distinction was already documented in `translations.ts`'s own header comment). New component follows `DisclaimerBanner`'s exact visual pattern, placed in the site footer. Verified live: hidden for `en`/`hi`, shown for `ta` (and, by the same locale check, every other non-en/hi locale).
5. **Persisted application-checklist progress**, keyed per scheme id, via a new `lib/schemes/checklist-persistence.ts` — versioned (`STORAGE_VERSION`), field-validated, discards on any shape mismatch (mirrors `lib/assessment/persistence.ts`), wired into `application-checklist.tsx` with the same isHydrated-safe pattern as `saved-schemes-context.tsx` (server render and first paint always start empty; a client-only effect restores real progress). Verified live: survives a reload, and switching to a different scheme shows that scheme's own (empty) progress rather than leaking the first scheme's state.

Full verification suite passed clean after every task and once more at the end: `tsc --noEmit`, `eslint --max-warnings 0`, `verify:engine` (34 schemes, all assertions green), `verify:chat-engine`, `next build`. i18n key parity (272 keys across all 12 locales, zero missing/extra) checked programmatically, not by inspection.

## Not completed safely — flagged rather than silently skipped

- **Uttar Pradesh / VSSY (`up-vishwakarma-shram-samman`) excluded from every task.** Task 1's own text nominally listed "Uttar Pradesh" among the state schemes to populate, but the same prompt's non-negotiable rules separately state "Do not touch VSSY data" as an unconditional rule. I read that rule as covering the whole record, not just its eligibility fields, so VSSY was excluded from Tasks 1 and 3 (it would otherwise have been the single best-documented candidate for the data-confidence note — its own comment already contains the most detailed residual-discrepancy writeup in the dataset). **Ask**: if "do not touch VSSY data" was meant more narrowly (e.g. only its eligibility-affecting fields), let me know and I can add its data-confidence note in a follow-up — no other VSSY field would need to change.
- **`mudra-tarun`, `nstfdc-term-loan`, `maharashtra-cmegp`, `andhra-pradesh-innovation-startup-grant`**: re-fetched their cited official sources this pass; none explicitly listed required documents or a step-by-step process (mudra.org.in and nstfdc.tribal.gov.in both just point applicants to a different portal/local office; mskvib.org's only procedural line is "apply online via cmegp.gov.in"; the AP policy PDF lists documents for other incentive tiers, not the base grant this record describes). Left unset with an inline comment rather than inferring anything.
- **`gujarat-scheme-for-assistance-startups`**: `startup.gujarat.gov.in` remains unreachable (robots.txt fetch failure) — third consecutive failed attempt across this and an earlier session. No document/step fields added.
- **`delhi-composite-loan-scheme`'s `requiredDocuments`** specifically: its sourceUrl only hedges ("Applicants may need Aadhaar card, income certificate... or occupation-related documents") and explicitly defers to a guidelines PDF that itself couldn't be fetched (robots.txt error, tried twice). Left unset — only `applicationSteps` was added, since those were stated as concrete numbered steps.
